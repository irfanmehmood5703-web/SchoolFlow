# Manual Ledger reference batch

Screens covered: Journal Entry, Add Expense, Add Other Income, GL Inquiry, Trial Balance, P&L and Balance Sheet, with an entry register and journal vouchers. Functional fields follow the supplied EDUBase references; SchoolFlow keeps its original green interface and original code.

All manual postings use integer paisa and a balanced journal header/line transaction. A transaction needs a configured active campus and an open non-overlapping Accounting Period. Accounts/groups must be active; each journal line has exactly one positive side. Expense rows debit Expense accounts and credit the selected Assets account. Other Income rows credit Income accounts and debit the selected Assets account. Empty trailing rows are ignored; populated invalid rows are rejected atomically. A unique submission token plus an actor-bound payload hash prevents duplicate posting and rejects changed-payload retries. Exact retries resolve the original voucher even after its period closes.

Posted entries are append-only in the application. Account code/name/group/class snapshots preserve voucher labels. Used accounts/periods cannot be deleted, used account groups cannot change, and posted-period date bounds cannot move. Period closure still needs all-campus Finance approval. Future correction workflows must create audited reversing journals, not edit history.

GL Inquiry includes all earlier posted activity in the opening balance and produces date/ID/line-ordered running balances. Trial Balance shows brought-forward debit/credit, current-period debit/credit, closing net debit/credit and group/class/grand totals. P&L supports campus/user/date filters, Income/Expense tabs, search and paging without changing report totals. Print includes the complete selected section regardless of search/paging. Balance Sheet is cumulative through To and includes cumulative net income in equity once; From remains visible context. Asset and liability/equity signs follow debit/credit accounting. Historical snapshots are netted by account ID, preventing duplicate net balances after renames.

All amounts come from SchoolFlow journals. Vendor screenshots’ school records, sample balances and personal details are not copied. Existing Admissions receipts, challans, discounts and payroll are NOT automatically posted to this ledger yet. Before financial use, explicit account mapping, idempotent source synchronization, receipt reversals and reconciliation must be implemented and tested. There are no fabricated bank transfers, payments or message deliveries.

Separate Finance permissions, full configured-campus grants, CSRF, the institute write lock and per-institute database routing protect the routes. Save & Print additionally needs Finance print permission. Real device/PDF visual verification and permanent trial database storage remain separate work.
