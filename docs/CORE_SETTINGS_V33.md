It implements the supplied remaining Core Settings screenshots as original SchoolFlow workflows. No EDUBase account, payment history, bank/IBAN, price, installer or private school record is copied.

## Attendance Alerts

Separate student/staff On controls and 0–1,440 minute delays, with Immediately/5/10/15/30/45/60/90/120 presets; Save Settings, Check now, unread count, Mark read and Mark all read. GET is read-only. Alerts use the current Pakistan date, active records, configured shifts and school holidays. A student campus/class/section/session cohort alerts only if none of its eligible active pupils has today's attendance after shift-in plus delay. Staff alerts use the earliest eligible active employee shift and require no mark among those employees. An unconfigured shift is not guessed. One historical alert group per kind/day is extended only for newly missing cohorts; repeated checks do not duplicate alerts or reset read state. Historical snapshots remain after attendance is subsequently recorded. Alert settings/history are private to the institute owner.

The existing optional awake-server worker checks saved enabled settings; `flask --app app attendance-alerts-check --code PRIVATE-CODE` and Check now offer explicit execution. Sleeping free hosting cannot guarantee clock-time alerts. Data is central for a future Owner App integration; the Owner App and push delivery are not represented as connected.

## Geo Location Attendance and registered devices

Per-campus saved latitude/longitude, 15–10,000 metre radius, Enable Geo Attendance and Allow only within Fence; optimistic version checks, exact input validation, radius slider, drag/click pin, 10-metre North/South/East/West controls and form reset. Pin selection does not save until Save Geo Location. Browser location is requested only when the user asks; no IP fallback or fabricated campus location is used. Pinned Leaflet 1.9.4 is vendored with verified JS/CSS SHA-256 and its BSD license. OpenStreetMap tiles load only when the user opens the map. Streets, detailed building zoom and a dark tile presentation work. Satellite, hybrid and topographic controls are wired to optional operator-configured HTTPS XYZ tile providers and remain disabled until configured; a map style is not fabricated. Set SCHOOLFLOW_GEO_MAP_LAYERS to a JSON object keyed by satellite/hybrid/topographic, each with url (containing {z}, {x}, {y}) and attribution; hybrid may also supply overlay_url. Only public browser-appropriate map credentials may appear in these URLs, never private integration keys. Saving campus coordinates cannot change provider configuration.

The device directory supplies employee-name search, campus filters, 25-row pagination and confirmed Delete/revoke. Actual browser device registration uses an active employee-linked staff login with the new **My Geo Attendance · self only** permission for that employee's campus. The navigation link appears only for eligible staff. Each browser receives a random credential; only its digest is stored by the server. The browser's device label is not claimed to be a hardware-attested identifier. Revocation stops that credential; authorised staff can register up to five browsers. Existing devices cannot attach to a deleted/recreated employee; deletion nulls their employee binding and preserves event history.

The self-only form never accepts a caller-supplied employee identity. HTTPS/session/CSRF, live account revision, campus rights, current geofence, device ownership, event-ID fingerprint, 60-second fresh location and 100-metre maximum reported accuracy are checked server-side. When within-fence is required, the location's accuracy circle must also be inside it. The server records its own event time, distance and accuracy rather than retaining exact coordinates. Identical retries replay their result; changed event reuse is rejected. The browser retains an exact uncertain event for retry with explicit cancellation guidance. Per-device new events are limited to 60/minute.

Valid geo events reuse existing shift/holiday/attendance-lock/manual-preservation/IN-before-OUT rules, the shared Daily record and the QR early-OUT policy. An accepted HTTP request can still report Not marked with an actual attendance-rule reason. Geo setup cannot silently alter payroll rules. Browser geolocation and credentials are not certified spoof resistance; actual phone/location testing and the separate Teacher App remain necessary.

## WhatsApp Service and Manage WhatsApp

Sender choice (SchoolFlow-managed / own WA Link), configured active provider and 3/7/14/30/90-day or indefinite local message-content retention. SchoolFlow-managed sending/message balance and a SchoolFlow Windows sender release are not configured; download/copy controls are explicitly unavailable unless the software owner publishes an original verified release. No other vendor's executable or Windows warning-bypass instructions are supplied.

The account manager has Name, write-only API Key, Base URL, active account selection, credential deletion, balance/stats refresh, actual provider QR request/display, remote account save/sync/inbox flags/view/rename/remove, linked-account selection, international mobile number, message, optional HTTPS media URL and retained local command history/status filters. Unretrieved balances and states are shown as unknown, never fabricated zero credits or successful connections. API keys and provider state are encrypted with Fernet and a dedicated operator-managed integration key, bound to the institute storage identity. Deleting a provider clears its secret and preserves command claims. Audit payloads do not include keys, message text or recipient numbers.

The optional adapter follows the documented request contract at https://walinkapi.com/api with exact endpoint `https://walinkapi.com/admin/api.php`. The screenshot's `api.walink.co` endpoint could not be verified as the same contract and is not silently contacted with a user's key. Arbitrary hosts/redirects are refused. Responses are bounded/redacted; QR images are validated, and arbitrary remote QR-image URLs are not fetched. The adapter requires real provider-account verification; response field compatibility and actual linking/delivery are not claimed from mocked tests.

No live provider request occurs unless `SCHOOLFLOW_WHATSAPP_ENABLED=1`; manual sending additionally requires `SCHOOLFLOW_WHATSAPP_SEND_ENABLED=1`, an explicitly selected linked account and configured private credentials. Delegated users also need institute-wide Core Settings Update and Communication Create rights. An encrypted command claim is committed before an external mutation. Matching request-token replay cannot resend; a timeout is Unknown and is never silently retried or labelled Sent/Delivered. Provider history is displayed only for the explicit response and is not retained as a second copy. Retention prunes old local send payloads but retains minimal command fingerprints to prevent later duplicate sends. Use `flask --app app whatsapp-history-prune --code PRIVATE-CODE` or the existing optional worker.

These controls do not pretend that existing SMS/WhatsApp communication queues have become a production delivery worker. Queued school messages, provider delivery receipts/webhooks, a managed balance service, actual provider credentials and a Windows sender binary require their separately verified integrations. No real message has been sent by this development/verification pass.

## SchoolFlow Subscription

Private primary-owner portal showing only operator-recorded services, cycle/price/active state, actual SchoolFlow payment details, date-filtered invoices, real paid dates, paid/discount/remaining totals and printable invoice/receipt statements. Empty configuration is explicitly empty; no sample balance, subscription, bank account or invoice is fabricated. Receipt IDs are filtered to the signed-in institute. Clients cannot edit charges, mark invoices paid, purchase a plan or trigger service suspension through this page.

Root control-database service/invoice/payment/profile tables are excluded from tenant schema routing. Operator-only CLI commands are `subscription-service`, `subscription-bank`, `subscription-invoice` and `subscription-receive` (run `flask --app app COMMAND --help` for flags). Amounts are integer paisa, snapshots retain invoice-time service/bank details, one invoice per institute/month is enforced, and unique payment references prevent replay. A conditional balance update prevents overpayment under concurrent operators. An unpaid print is explicitly a statement, not a payment receipt. Student fee/payroll accounts are untouched. The owner's actual prices, bank details and agreements remain to be supplied.
