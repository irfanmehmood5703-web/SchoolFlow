# School SIM sending runs

Open the SMS APK, connect the school-issued Phone ID/key once, allow SMS/phone permission, select the school SIM, and press **Send Messages**. Confirm the queue and SIM cost once. The app processes a snapshot of up to 200 already-released SMS, spacing message submissions by at least the selected **15, 20 (default), or 25 seconds**. A long message can use multiple SMS parts/credits. Carrier delay or missing callbacks can make the interval longer.

The app saves the connection/key in Android Keystore-encrypted private storage and remembers the SIM and interval. It does not silently start on launch, in the background or after a process restart. Keep it open while sending. Pause or leaving the app stops further dispatch; a message already handed to Android cannot be recalled. Queued messages added later require another explicit Start. Manual single-message review and result-upload recovery remain available.

The school website still prepares message snapshots and explicitly releases approved parent communication requests to a registered campus phone. Admission inquiry auto-queue remains opt-in. This update sends through the phone SIM, not WhatsApp or a paid SMS provider. It does not turn on real-school automatic sending as part of deployment.

Server batch IDs are idempotent and device/generation scoped. Snapshots exclude newly added jobs. The tenant write gate serializes claims, batch controls and dispatch authorization. A durable device cooldown enforces the selected interval across Pause/new runs/manual sends. Rotation/suspension invalidate old credentials. Starting a job is one-way; lost responses, process death, timeout and partial multipart failures never cause automatic resend. An uncertain result stops the run for operator review. Result reporting is idempotent and retries never call Android's send API.

“Submitted/sent” means all Android sent callbacks reported success. It does not prove recipient delivery. Missing/failed multipart callbacks are conservatively “uncertain”; the operator checks the phone SMS history and school outbox. The foreground worker waits for the previous result to be saved before moving on and stops on connection errors or unavailable SIM.

Automated checks use only fictional private schools, device keys, queues and numbers; no test calls a real SIM. Backend tests cover all intervals, cooldown boundaries and bypass attempts, finite snapshots, Pause, replay, callbacks, credential rotation and colliding school/device IDs. Native unit tests exercise monotonic timer state. Android compilation/lint and school-signed APK callback/download checks validate packaging. Physical Android/SIM/network sending remains an acceptance test on the school phone.
